# tnt-mutants

Мутационное тестирование Lua-кода для Tarantool. Отвечает на вопрос,
которого не задаёт покрытие: заметит ли хоть один тест, если код сломать.

```
$ tnt-mutants libs/journal/journal.lua
── база: libs/journal/test/
   набор зелёный за 0.4 с, предел мутанта 14 с
── libs/journal/journal.lua (тесты: libs/journal/test/, предел мутанта 14 с)
37 VALID MUTANTS
   мутантов: 37, убито: 97.3%
   выжили:
     var/mutants/generated/journal.mutant.12.lua
       58c58
       <     if #entries > limit then
       ---
       >     if #entries >= limit then
── итог: файлов 1, средний MSI 97.3%

Мутационная проверка не пройдена (1):
  libs/journal/journal.lua — 97.3% при пороге 100%
```

Утилита подменяет строки исходника — `>` на `>=`, `and` на `or`, `true`
на `false`, число на соседнее — и гоняет проверки на каждой подмене.
Мутант, которого не заметил ни один тест, назван в отчёте вместе с diff.
Планка по умолчанию — 100 % убитых.

## Что отличает

Мутационный прогон легко ослепить так, что цифра остаётся зелёной:
неизвестный аргумент luatest делает каждого мутанта «убитым» за долю
секунды, пара `/*` в строковом литерале прячет от генератора остаток
файла, слишком короткий предел времени убивает выживших, а файл без
единого мутанта проходит с нулевым кодом. Утилита считает все эти случаи
отказом, а не успехом:

- **база тем же исполнителем, что и мутанты** — набор обязан пройти
  на исходном коде той же строкой запуска, иначе сломанная строка
  показала бы сто процентов, ничего не проверив;
- **предел мутанта не короче двух длительностей набора** — иначе выживших
  убивал бы разброс времени; по умолчанию предел поднимается под набор сам,
  явный тесный — отказ до генерации мутантов;
- **отказ запуска — отказ проверки**, а не убитый мутант: исполнитель
  узнаёт, что luatest не начал проверок, и прогон валится даже при ста
  процентах;
- **ноль мутантов — отказ**, если файл не записан в список тех, где
  мутировать нечего;
- **слепые пятна генератора названы поимённо**: строки за парами
  `/*` и `{-`, до которых генератор не дошёл, и строки, которые он счёл
  мёртвым кодом;
- **правило исключения привязано к файлу** и обязано совпадать ровно с его
  строкой: мёртвое правило — отказ с номером строки в списке, широкое —
  названо вслух;
- **самопроверка** на файлах-образцах с заранее известным итогом: правка
  утилиты или правил, ослепившая её, валит `tnt-mutants selftest`.

Правила мутаций написаны под Lua: универсальные наборы ломают его
на комментариях `--`, неравенстве `~=` и словах `and`/`or`/`not`.

## Установка

Нужны bash 5, Python 3, `tarantool`, `tt` и luatest в проекте
(`.rocks/bin/luatest`).

```sh
git clone https://github.com/tnt-skein/tnt-mutants.git
cd tnt-mutants && make setup        # universalmutator в .venv, luatest для самопроверки
ln -s "$PWD/bin/tnt-mutants" ~/.local/bin/tnt-mutants
```

Проверить, что всё на месте: `tnt-mutants selftest` (около 25 с).

## Запуск

Из корня проекта:

```sh
tnt-mutants                  # файлы, изменённые относительно origin/main
tnt-mutants src/a.lua        # указанные файлы
tnt-mutants --list           # только назвать файлы, которые проверил бы прогон
```

Изменёнными считаются коммиты ветки поверх базовой, правки в дереве
и новые файлы — чтобы проверка не молчала ровно тогда, когда код пишется.
Набор проверок для файла — ближайший каталог `test/` вверх по дереву:
`libs/<пакет>/test/` для модуля пакета, `test/` для остального.

## Настройка

`mutants.conf` в корне проекта, образец — `mutants.conf.example`.
Любая настройка задаётся и переменной окружения с тем же именем;
окружение старше файла.

```sh
MUTANTS_SOURCES=(                      # что считается прикладным кодом
    ':(glob)src/**/*.lua'
    ':(glob)libs/*/**/*.lua'
    ':(exclude,glob)libs/*/test/**'
)

tests_for() {                          # свой выбор набора проверок
    case "$1" in
        src/*) echo 'test/' ;;
        *) return 1 ;;
    esac
}
```

Остальное: `MUTANTS_BASE`, `MUTANTS_MIN_MSI`, `MUTANTS_TIMEOUT`,
`MUTANTS_SUITE`, `MUTANTS_IGNORE`, `MUTANTS_EMPTY_LIST`, `MUTANTS_WORKDIR`,
`MUTANTS_LUATEST_FLAGS` — в документе.

## Эквивалентные мутанты

`sub(0, n)` и `sub(1, n)` в Lua дают одно и то же: такого мутанта не убить
ни одним тестом. Первое средство — переписать строку так, чтобы числа
не было (`s:sub(-#s, n)`); последнее — правило в `mutants.ignore`:

```
# Уровень броска: 0 и -1 в Lua значат одно и то же — место вызова
# не приписывается ни при том, ни при другом.
src/journal/fail.lua ^\s*error\(message, 0\)$
```

Правило действует только в своём файле и обязано совпадать с его строкой:
строку переписали — прогон откажет и назовёт правило, которое пора снять
или починить.
